# Hybrid SimpleSSD Release Note - 2026-06-15

## RAID Parallel RPC Submission

The JDP RAID integration now submits requests on different RAID member drives
in parallel while preserving request order within each drive.

RAID dependency phases remain ordered:

```text
READ: read phase
RMW/RCW: read phase -> write phase
FSW: write phase
DYNAMIC migration: read phase -> write phase -> migration phase
```

The latency of each phase is the critical path of its member drives. The
reported RAID stripe-operation latency is the sum of dependent phase critical
paths, rather than the sum of every SSD request latency.

This models parallelism within one RAID stripe operation. Host trace commands
are still replayed sequentially, so queue-depth and concurrent-host-I/O
throughput are outside the current model.

Managed RPC runs now keep a fixed-size logarithmic latency histogram in memory
and write only:

```text
<output-dir>/raid_latency_summary.json
```

The summary includes:

```text
count, average, min, max
P50, P90, P95, P99, P99.9
READ/WRITE/MIGRATE and RMW/RCW/FSW groups
critical-drive phase counts
```

Managed drive configs also force `EnableRequestLatencyLog = 0`. This disables
per-drive `rpc_request_latency.csv` output. SimpleSSD simulation ticks use
picoseconds.
